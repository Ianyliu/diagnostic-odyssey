# Community Pulse Phase F · decision addendum v0.2.1

Phase F uses fictional documents, approved fixture records, and offline research intake. It follows the v0.2 planning package and the owner’s later authorization. Instinct remains the preferred exploratory intelligence researcher where permitted. Automatic delivery by a supported native email action is the preferred first integration. A supported webhook could replace email after qualification. The deterministic lane owns registry-driven collection, evidence validation and operating state. Reviewer-governed publication is separate from both lanes.

## What Phase F supports

- **Change Ledger** displays approved fixture entries, distinct announced and effective dates, county applicability, source coverage, and correction tombstones.
- **Intelligence Brief** shows synthetic delivery receipts and untrusted research reports, including partial, no-substantive-change, and failed runs. Accepted reports remain distinct from candidate claims and approved events. Strategic synthesis, hypotheses, and potential planning implications carry their own labels.
- The read API returns a fresh projection from a replaceable data source. The preview uses only synthetic fixtures. The inbox polls every 30 seconds while visible, refreshes on focus, and clears its display when it cannot verify a current response. The approved release surface and future private inbox must use distinct authorized projections before using real data.
- The browser build requires `VITE_COMMUNITY_PULSE_ENABLED=on`. The Vercel handler requires `COMMUNITY_PULSE_MODE=fixture` in Vercel Preview and rejects contradictory deployment environment metadata. Enable both values for the authorized fixture-only preview branch. Use Vercel Authentication and the immutable deployment URL. The fixture API and browser flags fail closed on production.

The branch starts from `5b81f5fea2bdb3545e47302fde54c4b4c2a5f2b0`, which matched the remote default branch and production deployment when checked. The concurrent audit branch contains useful scientific characterization and refactor work. This implementation neither depends on those unpublished changes nor takes them into its branch. Use matching browser acceptance runs to compare canonical scientific behavior against the production-matched base.

## Local fixture workflow

Use the repo’s supported Node version. Open `http://127.0.0.1:5173/local-context`, choose **Policy & Access Change Ledger**, then open **Intelligence Brief**.

```sh
npm ci
VITE_COMMUNITY_PULSE_ENABLED=on COMMUNITY_PULSE_MODE=fixture npm run dev --workspace @diagnostic-odyssey/web -- --host 127.0.0.1
```

To test the manual fallback, use the synthetic JSON report and a private directory outside Git. For real operator work, use the same CLI only after approved data-handling arrangements are in place. The CLI’s intake store and the synthetic browser demo are separate.

```sh
PULSE_INTAKE_DIR="$(mktemp -d "${TMPDIR:-/tmp}/pulse-intake.XXXXXXXX")"
node --experimental-strip-types scripts/community-pulse/intake.ts import \
  packages/community-pulse/src/fixtures/research-report.json "$PULSE_INTAKE_DIR"
node --experimental-strip-types scripts/community-pulse/intake.ts list "$PULSE_INTAKE_DIR"
node --experimental-strip-types scripts/community-pulse/intake.ts inspect <receipt-id> "$PULSE_INTAKE_DIR"
```

Replace `<receipt-id>` with the ID printed by the first command. The tool prints a receipt on duplicate or rejection and uses exit status 2 for quarantine. Import accepts JSON or Markdown in the two formats in the [worker contract](WORKER_CONTRACT_v0.2.1.md). The CLI retains accepted candidate reports and rejection metadata in an owner-only local store. It never fetches source URLs, adds to the approved ledger, or writes rejected message bodies to disk. Delete the temporary store when no longer needed.

## Connecting real Instinct email after authorization

1. Confirm vendor permission for organizational research and downstream use. In a permitted, isolated Instinct account, establish whether native recurring tasks can send to one fixed project address without personal mailbox access, web automation or human confirmation on each delivery. Ask the provider for supported structured delivery or webhook documentation. If the account cannot meet those requirements, use manual import while qualifying another supported transport. [Instinct terms](https://instinct.com/terms), [privacy policy](https://instinct.com/privacy-policy), [acceptable use](https://instinct.com/acceptable-use-policy)
2. Choose a dedicated project mail domain or subdomain, for example `pulse-mail.example.invalid` as an illustrative placeholder. Verify you control its DNS and that its MX can be dedicated to Cloudflare without disrupting existing mail. In **Email Routing**, enable routing for the intended domain, review the generated MX/TXT changes, and create an exact recipient such as `reports@pulse-mail.example.invalid`. Route it to a staging Email Worker and leave catch-all disabled. Use a private staging R2 bucket with lifecycle policy. Bind it only to the trusted receiver. The sender receives the destination address and report contract only. [Cloudflare routing setup](https://developers.cloudflare.com/email-service/configuration/domains/), [Email Worker handler](https://developers.cloudflare.com/email-service/api/route-emails/email-handler/), [R2 lifecycle](https://developers.cloudflare.com/r2/buckets/object-lifecycles/)
3. Qualify the receiver with one permitted synthetic message before enabling recurrence. Confirm the delivered MIME is UTF-8 text or structured JSON and verify the real envelope/header identity, permitted project recipient, aligned DKIM with full report coverage, and passing DMARC. Cloudflare documents prepending the authentication results it computes. Establish the trusted first ingress result and auth service identifier from a real staging delivery, test forged earlier/repeated headers, and fail closed on missing or ambiguous trusted evidence. Do not infer trust from a From field, arbitrary Authentication-Results, Subject, Message-ID, or the report itself. Treat DKIM as domain authentication and verify that the chosen sender/account arrangement prevents other users of a shared sending domain from impersonating the intended project sender. If a stable authenticated sender identity cannot be established, leave that transport disabled. [Cloudflare authentication metadata](https://developers.cloudflare.com/email-service/api/route-emails/email-handler/)
4. Connect the Email Worker to the common intake contract. Reject streaming payloads over 256 KiB and decoded reports over 64 KiB, with metadata-only quarantine. Add recipient and identity rate limits, replay retention, trusted timestamps, and conditional create/update for delivery receipts, content digests and logical run IDs. Retry identical delivery safely. Commit candidate bytes before marking their receipt ready, reconcile incomplete writes, and keep run failures visible. Neither the Worker receiver nor Instinct can activate the public pointer. A separately authenticated dashboard reads an internal projection, and the publisher reads explicitly approved bytes through its existing policy.
5. After staging passes, configure native hourly incremental scout, daily comprehensive synthesis, weekly strategic review and explicitly initiated on-demand research with fixed destination and report types. Use unique per-task run IDs, send a no-change receipt for successful empty runs and use partial or failed receipts for incomplete work. If deliveries stop entirely, the receiver reports missed expected slots independently. Configure kill, credential revocation and route-disable procedures before starting recurrence.
6. If routing is unavailable, use a dedicated Gmail mailbox with a trusted adapter and only necessary read authorization. Avoid a personal mailbox. Use OAuth `gmail.readonly` for body access, a private trusted polling worker with per-mailbox durable cursor, and a bounded resync when Gmail history returns 404. Validate receiver-added authentication results, dedupe with Gmail’s immutable message ID plus digest and run ID, and fence cursor advancement. Review OAuth verification and organizational permission first. Pub/Sub push can wait. [Gmail synchronization](https://developers.google.com/workspace/gmail/api/guides/sync), [Gmail scopes](https://developers.google.com/workspace/gmail/api/auth/scopes)

**Effort and cost.** Estimate 3–5 engineering days after permissions and account access to implement the Worker adapter, durable conditional intake and protected private projection, plus 1–2 days for domain/account qualification, incident controls and sign-off. The Gmail alternative adds roughly 2–3 engineering days plus any OAuth verification time. Hourly, daily and weekly receipts total about 754 messages in a 30-day month before manual runs. At 64 KiB each, a month of decoded reports is below 48 MiB, plus receipts and raw-retention policy. Cloudflare lists inbound routing separately from paid sending. R2 Standard includes 10 GB-month free storage, 1 million Class A and 10 million Class B requests per month. Check actual plan eligibility, domain cost, account-wide Worker CPU/request budgets and polling volume. These estimates carry no paid inference and no automatic paid fallback. [Email pricing](https://developers.cloudflare.com/email-service/platform/pricing/), [Workers limits](https://developers.cloudflare.com/workers/platform/limits/), [R2 pricing](https://developers.cloudflare.com/r2/pricing/)

The next implementation track is a staging-only receiver with a private R2 receipt store, an authenticated inbox projection and deterministic replay/retention tests. Real source collection, vendor scheduling, editorial publication and public or government-facing validation each retain their separate approvals.
