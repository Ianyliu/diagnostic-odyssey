# AgentMail staging transport

AgentMail is the first-choice hosted inbox for the Community Pulse pilot. The Worker trusts a signed notification to request one exact inbox message, then checks AgentMail's receiver-produced authentication results and original plain-text MIME representation when present. The v0.2.1 intake validator, private R2 receipt journal, and protected Vercel history remain in the path. The direct Cloudflare Email Worker remains supported as an alternative.

## Owner setup

1. Sign in to the existing verified **Free** account in the [AgentMail console](https://console.agentmail.to/) and review the terms for this private application pilot. Free use and future application integration depend on the applicable tier and account eligibility. Use the existing dedicated hosted `agentmail.to` inbox. Copy its exact **inbox ID** and **receiving email address** from AgentMail. Share only the receiving address with Instinct. [Create an inbox](https://docs.agentmail.to/knowledge-base/creating-first-inbox) · [Terms](https://www.agentmail.to/legal/terms)
2. In AgentMail **API Keys → Create New API Key**, create an inbox-scoped API key with the exact inbox as its scope and the explicit whitelist `{"message_read":true}`. If using the documented API with an owner credential, send `POST /v0/inboxes/{URL-encoded-inbox-id}/api-keys` with the body `{"name":"community-pulse-staging","permissions":{"message_read":true}}`. An omitted permissions object grants much broader access. Store this key directly in Worker Secrets as `PULSE_AGENTMAIL_API_KEY`. Reserve the owner credential for account setup. The Worker needs no send, delete, label, or webhook management permission. [Scoped API key](https://docs.agentmail.to/api-reference/inboxes/api-keys/create) · [Permissions](https://docs.agentmail.to/permissions)
3. In [Workers & Pages](https://dash.cloudflare.com/?to=/:account/workers-and-pages), register the account's Free `workers.dev` hostname. In [R2](https://dash.cloudflare.com/?to=/:account/r2/overview), review Standard usage billing before the owner activates R2 and creates the private `community-pulse-staging-intake` bucket. Use the [Phase S0 retention setup](PHASE_S0.md) for the `s0/` prefix, including AgentMail checkpoint and receipt metadata. Leave public access and public bucket domains disabled. If activating R2 would require a paid plan or a billing change the owner has not approved, stop at that step. [R2 activation](https://developers.cloudflare.com/r2/get-started/) · [R2 pricing](https://developers.cloudflare.com/r2/pricing/)
4. Deploy `community-pulse-staging` with its three checked-in kill switches off. From the tested revision, run `node scripts/community-pulse/build-worker.mjs /absolute/private/path/worker.mjs`. Upload that module with [the staging metadata](../../apps/pulse-worker/staging-upload.json), bind the private bucket as `PULSE_INTAKE`, and enable the per-Worker `workers.dev` endpoint. Keep per-version public preview URLs disabled. An operator needs scoped Workers Scripts Write and Workers R2 Storage Write if managing the bucket. The domain-free transport needs no zone, DNS permissions, custom domain or MX changes. [Worker upload API](https://developers.cloudflare.com/api/resources/workers/subresources/scripts/methods/update/) · [workers.dev](https://developers.cloudflare.com/workers/configuration/routing/workers-dev/)
5. In AgentMail **Webhooks**, create an inbox-scoped endpoint for only `message.received` at `https://community-pulse-staging.<account>.workers.dev/v1/agentmail/webhook`. From **Workers & Pages → community-pulse-staging → Settings → Variables and Secrets → Add → Secret**, copy the generated `whsec_…` directly to Worker Secrets as `PULSE_AGENTMAIL_WEBHOOK_SECRET`. Set `PULSE_AGENTMAIL_INBOX_ID` to AgentMail’s exact hosted inbox ID, which is the full receiving email address. Set `PULSE_EXPECTED_SENDER` to the exact managed Instinct mailbox. Leave the separate native Cloudflare Email Routing recipient unset for this pilot. The optional `PULSE_AGENTMAIL_DKIM_DOMAIN` defaults to the managed sender's From domain. Only configure a parent signer once the actual provider verdict establishes it. Keep the address and secrets out of Git, logs, browser bundles and chat. [Webhook setup](https://docs.agentmail.to/webhooks-overview) · [Signing secrets](https://docs.agentmail.to/webhook-verification)
6. Keep Vercel Authentication enabled under **Project → Settings → Deployment Protection**. In **Project → Settings → Environment Variables → Add New**, select **Preview** and the exact feature branch. Follow the [branch-only server credential setup](PHASE_S0.md). Create an independent `PULSE_INBOX_TOKEN` for Worker reads and set the corresponding preview-only `PULSE_STAGING_WORKER_TOKEN`. Use the Worker root in `PULSE_STAGING_WORKER_URL`. Set `PULSE_STAGING_INBOX_ENABLED=on` only on the authorized staging branch when ready and redeploy the exact SHA. Intake secrets stay in Cloudflare. The current synthetic URL needs no new build to demonstrate existing history or threads.

## First synthetic delivery

1. Save one completed synthetic v0.2.1 report from the [Instinct contract](INSTINCT_AGENT_CONTRACT_v0.2.1.md) with a unique run ID. Run `node --experimental-strip-types scripts/community-pulse/validate-report.mjs /private/path/report.json`. Require exit 0. Set `PULSE_AGENTMAIL_SYNTHETIC_REPORT_SHA256` to the printed `canonical_report_sha256`. The gate permits only that report in synthetic mode.
2. Enable `PULSE_STAGING_ENABLED=on` and `PULSE_AGENTMAIL_MODE=synthetic`. Leave reconciliation and recurring Instinct off. Verify that anonymous requests to the dashboard hit Vercel Authentication, Worker reads without the separate bearer return 401, and unsigned webhook requests fail. Then authorize exactly one delivery from the managed Instinct sender to the dedicated address. Send the preflighted JSON as the plain-text body, without HTML-only content, fencing, attachments, or a reply trail.
3. Verify AgentMail's delivery status and the exact message's `authentication_results`. Confirm the exact From mailbox, `dkim=pass` from the configured aligned signer, `dmarc=pass` for the From domain, and no ARC surrogate. Confirm one accepted report with the expected canonical digest, along with updated delivery health in the protected history. The protected `?inspect=receipts` view shows the `agentmail-staging-email` provider, pending review, and the content digest. Compare the receipt content hash against provider-extracted UTF-8 text, which can differ byte-for-byte from the outbound body. Test replay of the same provider delivery and a separate synthetic interrupted-write recovery in the offline suite.
4. Keep subsequent real reports and any recurring work paused until the owner accepts transport qualification. The named mailbox is sufficient for a digest-pinned delivery and stays in synthetic mode for this phase. Broad qualified intake and reconciliation remain disabled. The separate qualified mode requires a private random address as an additional control. Reconsider controls before any later authorization for ongoing intake. No recurring trigger is installed by the code or upload metadata.

## Trust, limits, and recovery

AgentMail signs the exact webhook body with Svix. The adapter checks the signature and freshness before JSON parsing, accepts only the configured inbox and `message.received`, and uses the fixed AgentMail API to retrieve that message. It never follows `body_url`, raw-message links, source links or attachment URLs. The exact inbox and managed From, provider DKIM/DMARC results, and the pinned synthetic digest together limit the path. A guessable inbox can attract unrelated email and consume the bounded intake quota. Those results are domain-level evidence. They cannot prove which individual controls the account or report the same signed-header and body-length details as direct Cloudflare Email Routing. AgentMail may omit the signer domain when multiple signing domains are present. If the synthetic delivery lacks required fields, leave intake closed pending provider clarification instead of relaxing the gate. [Webhook signing](https://docs.agentmail.to/webhook-verification) · [Get Message authentication fields](https://docs.agentmail.to/api-reference/inboxes/messages/get)

The request body is capped at 128 KiB. Email metadata size is capped at 256 KiB and the independently validated decoded v0.2.1 report stays at 64 KiB. AgentMail keeps the combined message body inline in a webhook only through 64 KiB. The fixed message API supplies the original plain-text representation regardless. Duplicate upstream notifications and recovery share the exact inbox/message identity. The durable marker is completed only after the shared receipt is durable. Invalid content yields bounded metadata-only quarantine. Incoming reports gain no publication authority. [Webhook body size and retry behavior](https://docs.agentmail.to/webhooks-overview)

Recovery lists two messages per tick, begins with at most 48 hours, and persists its continuation in R2. Completed scans use a two-hour overlap for the next scan. It uses the same provider lookup, sender checks and durable intake as signed delivery. The sweep is for transient misses. AgentMail’s time filters use the listing timestamp, so sender-dated mail with extreme dates can fall outside the sweep. Review backlog against retained mail after a longer gap, a provider outage or an exhausted page window. AgentMail can stop retrying and does not automatically replay events from a disabled period. A single enabled Worker must still obey the account's CPU and subrequest budgets. [List Messages](https://docs.agentmail.to/api-reference/inboxes/messages/list) · [Workers limits](https://developers.cloudflare.com/workers/platform/limits/)

AgentMail advertises Free at $0 with no card, three inboxes, 3,000 emails per month, 100 per day, 3 GB storage and signed webhooks. Its separate rate-limit guide describes 100 daily sends and no separate monthly sending cap. The docs reviewed do not establish a distinct hard inbound quota or SMTP size limit. The pilot's own limits remain authoritative. About 755 scheduled reports in a 30-day month before on-demand research leaves headroom against the published volume, subject to actual account eligibility and usage. Cloudflare R2 Standard free allowances are account-wide and overages can incur charges. [Pricing](https://www.agentmail.to/pricing) · [Rate limits](https://docs.agentmail.to/knowledge-base/rate-limits) · [R2 pricing](https://developers.cloudflare.com/r2/pricing/)

AgentMail has separate mailbox retention. Its privacy terms permit need-based retention and the optional 24-hour expiry is early access and off by default. Have the owner review and delete staged mailbox contents using their account controls as required. The runtime key cannot delete. R2's 30-day default retention does not delete upstream copies. Limit the pilot to eligible public-source research and synthetic fixtures without personal or health information. [Security and retention](https://docs.agentmail.to/knowledge-base/security-compliance) · [Privacy notice](https://www.agentmail.to/legal/privacy)

For rollback, switch `PULSE_AGENTMAIL_MODE=off`, set `PULSE_AGENTMAIL_RECONCILE=off`, and disable the exact AgentMail webhook. Switch off the Worker master flag to stop protected reads as well. Rotate the scoped API key and signing secret if exposed. Preserve existing authorized receipts and let existing retention apply. Reenable only after repeating synthetic qualification.

CloudMailin remains the second choice. It advertises a Free hosted mailbox transport, with a different documented HTTP authentication scheme. It would need separate sender-attestation and replay qualification. A dedicated Gmail mailbox remains a manual fallback. Gmail push relies on Google Cloud Pub/Sub, so it is out of scope for this staging pipeline. [CloudMailin pricing](https://www.cloudmailin.com/plans-and-pricing) · [CloudMailin delivery authentication](https://docs.cloudmailin.com/receiving_email/securing_your_email_url_target/) · [Gmail push](https://developers.google.com/workspace/gmail/api/guides/push)
